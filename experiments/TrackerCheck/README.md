# TrackerCheck — 추적기(`Tracker.cs`) 검증 (2026-10-24)

유고 감지 구상의 1단계. 기준 영상 test4·test5 의 **모든 프레임**을 본 앱 `ProcessFrame` 과 같은 길
(BGR→BGRA→SKBitmap→`RunObjectDetection(0.3, 0.7)`, `TargetClasses` 필터)로 검출해 CSV 로 남기고,
그 검출로 루트 `Tracker.cs` 를 돌려 트랙을 본다. 검출은 GPU 로 한 번만 하고, 파라미터를 바꿀 땐 `track` 만 다시 돌린다.

```bash
dotnet build experiments/TrackerCheck/TrackerCheck.csproj -c Release
```

```bash
experiments/TrackerCheck/bin/Release/net10.0-windows10.0.19041.0/TrackerCheck.exe detect
```

```bash
experiments/TrackerCheck/bin/Release/net10.0-windows10.0.19041.0/TrackerCheck.exe track
```

- `detect`: `out/test4.dets.csv`·`out/test5.dets.csv` (약 45초). 영상은 gitignore 대상이라 워크트리엔 없어서 저장소 루트의 `publish` 에서 읽는다(`RepoPaths.VideoDir` — 절대 경로를 박지 않는다). 모델은 저장소 루트 `best.onnx`
- `track [이름=값 ...] [Step=N] [noreset] [noframe]`: 트랙별 시작·끝·관측 비율·라벨 흔들림, 의심스러운 연결, 끊김 후보, 테두리 멈춤 판정,
  **목표 정지 차량 통과/실패**를 `out/report.txt` 에. 트랙 배정과 그 프레임의 정지 판정(`stationary` 열, 1 = `IsStationary`)은 `out/<영상>.tracks.csv`
  - test4 는 카메라가 도는 10.5~11.4초·20.5~21.2초에 `Reset()` 하고 그동안 넣지 않는다 (전환 감지기가 할 일을 흉내). `noreset` 이면 그대로 넣는다
  - `Step=N`: N 프레임에 하나만 넣는다 (프레임레이트가 바뀌어도 같은지)
  - 추적기에 프레임 크기(test4 1280×720 · test5 1280×854 — `frameSizes`, `detect` 가 영상과 맞는지 본다)를 준다. `noframe` 이면 안 줘서 테두리 처리 전(예전) 판정 — 아래 "화면 가장자리 멈춤 판정"
- `selftest`: 합성 장면으로 테두리 멈춤 판정을 본다. 앱 연결(2026-11-02)도 본다 — `UpdateTagged` 가 번호·정지를 `Update` 와 같게 붙이는지, 화면 HUD 의 가상 시계(새 화면 사이 250ms 상한)가 정지 화면에서
  번호를 지키고 출력이 수렴하는지 (영상·GPU 불필요, 결정적, 종료 코드 = 실패 수)
- `views`: 화면 식별(`ViewIdentity.cs` — ORB + 호모그래피)을 test4 의 세 화면·test1~3·5 의 실제 프레임에서 재 본다 — 기준(행) → 새 화면(열) 인라이어/격자 칸 행렬, A2 기준 상세(특징점·좋은 짝·인라이어·이동·배율·원근), 식별 한 번의 시간 내역, 같은 화면에 흔들림(옮김·확대·회전·밝기·노이즈·JPEG)을 줬을 때. 결과(2026-11-03): 같은 화면 300~540, 다른 화면 최대 8
- `mkrevisit [출력 경로]`: test4 조각을 하드 컷으로 이어 같은 화면이 다시 나오는 30초 영상을 만든다 — A 0~8 → B 12~18 → A 1~9 → C 22~26 → B 14~18 (기본 `out/test4_revisit.mp4`, 33 MB). `tests/ui/Test-ViewIdentity.ps1` 이 쓴다 (원본의 조각이라 저장소엔 없다)
- `dedup [Every=N]`: 본 앱 표시 경로의 중복 박스 필터(`Detection.cs` 의 `DuplicateBoxes`) 전후를 `out/dedup.txt` 에 (아래 "중복 박스 필터").
  ① 저장한 검출로 박스 수 전후·뺀 박스 종류·목표 정지 차량 자리의 이중 박스 ② SAHI — 타일 검출을 GPU 로 다시 해(N 프레임에 하나, 기본 15) 병합 결과 전후
- `render <test4|test5> <x,y,w,h|full> <배율> <초...>`: 트랙 ID(번호+라벨 첫 글자, 정지 판정이면 뒤에 `*`)를 그린 프레임을 세로로 이어 `out/render_*.png` 로. 의심 연결은 이걸로 눈으로 봤다

추적기의 중복 판정을 `Detection.cs` 의 `DuplicateBoxes` 로 빼서 본 앱 표시 경로(`ProcessFrame`·HUD·SAHI)도 같은 규칙으로 중복을 뺀다.
빼낸 뒤에도 `track` 결과(`report.txt`·`*.tracks.csv`)는 바이트 단위로 같다.

SAHI 를 타일마다 먼저 거르면 `MergeNms` 입력이 바뀌어 어긋난다. 예: test5 44.75초 — 타일 경계(x=640)에 걸린 탱크로리에서
아랫부분 박스(truck 0.32)가 같은 타일의 큰 박스(truck 0.67)의 중복으로 빠지고, 그 큰 박스는 병합에서 다른 타일의 좁은 박스(truck 0.83)에 지워져
아랫부분을 덮는 박스가 사라졌다. 병합 뒤에 거르면 병합 결과는 그대로이고 뺀 박스는 정의상 남은 박스의 중복이다 → 본 앱은 병합 → 필터.

## 화면 가장자리 멈춤 판정 (2026-10-31, 이슈 #10, `track`·`selftest`)

화면에 들어오거나 나가는 물체는 보이는 부분까지만 박스가 잡혀 테두리 쪽 변이 테두리에 머문다. 멈춤 판정은 축마다 '덜 움직인 변'으로 재므로
(위 2번 — 한쪽 가림에 끊기지 않으려고) 그 변이 0 이 되어 움직이는 차가 정지가 됐다. 정지면 예측이 꺼지고, 화면을 나간 뒤에도 10초 남아
같은 자리에 새로 잡힌 차가 그 ID 를 물려받는다. `Tracker.Update(dets, ms, 프레임 폭, 높이)` 는 테두리 2px(`BorderMargin`) 안의 변을
(지금·기준 박스 어느 쪽이든) 빼고 그 축을 반대쪽 변으로 잰다. 정말 멈춘 채 걸친 차는 반대쪽 변도 안 움직여 정지로 남는다.
두 변이 다 닿은 축은 잴 수 없어 판정을 그대로 둔다(보이는 움직임만으로 허용치를 넘으면 정지를 푼다). 크기 없는 `Update(dets, ms)` 는 예전 그대로다 —
실데이터(Step 1·2·3·5)에서 옛 `Tracker.cs` 와 프레임마다 추적기 상태 전부(트랙 ID·정지 판정·마지막 시각·박스)가 바이트 단위로 같다.

`track` 은 관측마다 추적기의 정지 판정과 따로 잰 움직임(최근 ~1초 박스 중심 이동이 추적기 허용치를 넘음 — 테두리에 걸쳐 움직이는 차도 중심은 움직인다)을 맞댄다.
테두리 띠(박스 변과 테두리의 최소 거리)는 추적기 여유와 따로 2px 안·3~8px·안쪽으로 고정했다.

- 바뀐 건 정지 → 움직임 143행(트랙 17개)뿐이고 반대는 없다. 모두 오른쪽(·오른쪽 아래) 테두리로 들어오는 차 — `render` 로 확인(예전엔 `*`)
- 테두리에 걸친 채 정지로 남은 것: 아래 테두리에 잘린 채 서 있는 차(뷰 1 ID 40, 9초 내내)와 오른쪽 끝에서 거의 안 움직이는 차(ID 147, 0.5초)
- 트랙 배정(`tracks.csv` 의 ID 까지)은 Step=1·2·5 에서 예전과 바이트 단위로 같다 — Step=1 이면 위 "결과" 표 그대로
  (트랙 160 · 재연결 9 · 튐/크기 급변 26 · 끊김 후보 9, test5 14 · 1 · 2 · 0). Step=3(10fps)에선 오른쪽에서 들어와 기둥 뒤로 도는 소형 트럭
  (위 표의 ID 151)이 예전엔 들어오는 동안 정지로 판정돼 예측이 꺼져 둘로 끊겼고, 지금은 Step=1 처럼 하나로 이어진다(트랙 228 → 227, 튐 45 → 46).
  목표 정지 차량은 모든 Step 에서 통과
- `noreset`(전환에 Reset 안 함)에선 예전 판정이 이슈의 증상을 그대로 냈다: 카메라가 도는 21.03초 왼쪽 아래 구석의 박스(-2,690,99×30)가 정지로 남아 7.03초 뒤
  같은 구석의 다른 차(1,692,164×27)에 ID 를 넘겼다(다시 이음). 지금은 그 연결이 없다(재연결 9 → 8, 전환을 넘은 트랙 56 → 55)
- test5 는 아무것도 안 바뀐다 — 테두리 박스 351개(아래 테두리로 빠지는 차) 모두 원래도 정지가 아니었다(비스듬히 움직여 반대 축이 움직임)
- `BorderMargin` 스윕: 0 이면 테두리 1~2px 안에서 끝나는 박스가 빠져 움직이는데 정지 9 (3) · 3~8px 3 (3) · 남은 트랙 1 이 남는다. 1·2·4·8 은 결과가 모두 같다 → 2(SAHI 경계 여유와 같음)
